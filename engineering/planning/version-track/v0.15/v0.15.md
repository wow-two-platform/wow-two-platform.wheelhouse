**Status:** 🔄 In progress · **Type:** Feature · **Started:** 2026-11-10

`wheelhouse`): Wheelhouse deploys Events, SCFD and SCFD Adapters on dev beside `files-dev`, types their registrations in

citing `events-integration #N`. Backups, planned for v0.15, move to v0.16; v0.14's open rows stay with the Files goal.

### Iteration 1 — A secret linked across products

events-integration #22: Events calls SCFD as Ocharo Identity's client `events`, whose secret is generated on
`ocharo-dev` and must reach `events-dev` unchanged; `from` stays inside one product and the vault never shows a value.

- [x] Ability to link a target's key to another product's key in the same environment, and to unlink it
- [x] Ability to render a linked key from its source's current value: a vault secret's version, a stored setting
- [x] Ability to read a linked key's source, secrecy, version and fingerprint in the environment's settings, and to see
  it unapplied after its source changes
- [x] Refuse a link across environments, within one product, to a linked key, to or from a derived key, or onto a key
  the release links; refuse a value saved to a linked key
- [x] Ability to link and unlink a key from the environment's settings in the console
