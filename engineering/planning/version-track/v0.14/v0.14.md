# v0.14 — Files' shared host

*Last updated: 2026-11-08*

**Status:** 🔄 In progress · **Type:** Feature · **Started:** 2026-11-08

The Files integration goal (`wow-two-sdk-beta.files` `engineering/planning/files-integration.md`, lane `wheelhouse`):
Wheelhouse deploys B, WoW2's shared files host, on dev, types its registrations in Ocharo's Identity and its `ocharo`
tenant, and moves Ocharo dev's legacy files into it. The picks and their reasons are backlog rows citing
`files-integration #N`. Backups, planned for v0.14 on 2026-11-02, move to v0.15: the Files goal runs first.

### Iteration 1 — Host aliases

files-integration #21, #28, D1 (a): B's audience is each tenant's own `https://files.{domain}/`.

- [x] Ability to name extra hosts for a target's site beside its host, validated and unique across the target
- [x] Ability to route each alias with its own routers and certificate, public sites only
- [x] Ability to hand a service every host it answers on in `AllowedHosts`, `Sites:<site>:Url` still the primary
- [x] Ability to edit and read a site's aliases in the environment's form and page

### Iteration 2 — Migration job, dev slice

files-integration #28, t9 W1–W9. Waits on Files' import API, `files` CLI image and import tokens, and platform's
`engineering/deployment/files-migration.yml`.

- [x] Ability to read a product's migration manifest from its release
- [x] Ability to plan and dry-run a migration: files and bytes per source on the source host (the mover counts; Files)
- [x] Ability to preflight a migration: tenant, credentials, source reachable, Files healthy (`GET {filesUrl}health`, 5 s)
- [x] Ability to run the mover on the source host, sources read-only, the import token over stdin
- [x] Ability to verify count and checksum parity per source and hand the id map to the product (by import id; the mover compares)
- [x] Ability to cancel a migration job and follow its file and byte progress (console "Move files to Files…")

### Iteration 3 — B on dev

files-integration #28, #21, #32. Waits on a Files release with its Identity and tenant keys, and on platform's
registrations for `files`.

- [ ] Register product `files` and target `files-dev` on the products host, with its `app` hosts
- [ ] Type `Resources:2:Uri`, `Resources:2:SignalUrl` and each caller's `Files:BaseUrl` on `ocharo-dev`
- [ ] Type the `ocharo` tenant on `files-dev`: `Files:Auth:Issuers:0:Issuer` (Ocharo's Identity), `:TenantId`
  `ocharo`, `:Audiences:0` `https://files.{ocharo domain}/`, and `Files:Auth:Audience`; the `app` site's host is
  Ocharo's Files host, and bytes share `Storage:Root` under `{tenant}/` (files lane, 2026-11-08)
- [ ] Deploy Files to `files-dev` and run its dev check
