# v0.12 — Config check

*Last updated: 2026-11-02*

**Status:** 🔄 In progress · **Type:** Feature · **Started:** 2026-11-02

Owner 2026-11-02: each service checks its rendered settings before any restart, so a wrong or missing value stops the
rollout while the previous release still serves. Contract: hub `deploy-descriptor.md` § Config check and the service
`config-check.md`; the be sdk hosts the verb since 10.0.96-beta. Identity is the first consumer. Backups stay in v0.13.

### Iteration 1 — Descriptor

- [x] Ability to declare `configCheck:` items in `deploy.yml`, checked by the pipelines generator behind a new tag

### Iteration 2 — Runner

- [x] Ability to run each `configCheck:` item after migrate, before the first wave
- [x] Ability to run it on every settings-only apply, from the image the target runs
- [x] Ability to run it in the rollback gate, after the older image's `migrate check`
- [x] Ability to stop the rollout on a refusal, a failure or a timeout, naming each finding

### Iteration 3 — Console

- [x] Ability to see each config check as a rollout step, with its findings

### Iteration 4 — Fixes

- [x] Fix a database reset inside the post-rollout watch reading as degraded

### Verification

- [x] Run the pipelines generator tests → all pass, the new tag released
- [x] Build the backend and the frontend → no warnings, no errors
- [x] Run runner, Unit, Integration, E2E and Migrations → all pass
- [x] Run the frontend tests and `vue-tsc` → all pass
