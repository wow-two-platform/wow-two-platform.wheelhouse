- [x] Ability to wire a products VPS privately: bootstrap role, PostgreSQL, private ingress, tailnet SSH
- [x] Ability to pull private product images on a products host with a read-only token
- [x] Ability to reach a privately deployed product by tailnet name or address
- [x] Ability for a product's manifest to declare the paths each service serves per site
- [x] Ability to register servers from OVH or Contabo, with a root-only image first step
- [ ] Ability to connect a Cloudflare account with a scoped token and see its status
- [ ] Ability to sync a Cloudflare account's zones and choose from its domains
- [ ] Ability to bind a product's sites to a domain per environment with derived hosts
- [ ] Ability to plan, apply and drift-check a binding's DNS records
- [ ] Ability to wire a products VPS with public ingress and DNS-01 certificates in one step
- [ ] Ability to route sites by host and path, with priorities and `www` redirects
- [ ] Ability to apply a binding change as a recorded routes deployment, without a release
- [ ] Ability to unbind a host and remove only the records Wheelhouse owns
- [ ] Ability to hand each service its site URLs and allowed hosts
- [ ] Ability to track domain, certificate and token expiry

`repair-networks.sh` in a maintenance step (vps.md § Network repair).

- [ ] Ability to see each host's kit version and refresh it from Wheelhouse
- [ ] Ability to manage the control host's firewall, SSH and updates like a products host
- [ ] Ability for CI to reach the control host over the tailnet, closing public SSH
- [ ] Ability to schedule host reboots and Docker and Tailscale upgrades
- [x] Ability for fixed container addresses (the ingress's `.2`) to survive a reboot
- [ ] Ability to rebuild the control host from backups, rehearsed
- [ ] Ability to be warned before a credential, key or certificate expires
