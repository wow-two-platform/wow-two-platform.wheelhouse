Self-deploy (decisions 64–66, built 2026-10-19; deployment.md § Wheelhouse deploys itself): the two ticked lines are
built and proven by tests and the local rig (`rehearse.py self-deploy`: Wheelhouse's release to its dev through the

that rolls back, the boot read-back and the dialog — and proven in parts; the console replacing itself is proven on the

### Iteration 24 — Products of several repositories

Decision 70 (owner 2026-10-21): Ocharo is one product, `ocharo`, of Platform, Studio, Marketing and Assets. A product
release is a set of repository releases (architecture.md § Release sets); the merge and prod's move are in
deployment.md § Products of several repositories.

- [x] Ability for a product to list several repositories, each with its own release source
- [x] Ability to refuse a service, site or volume that two repositories of a product declare
- [x] Ability to compose a product release from each repository's release, and from a commit build for dev
- [x] Ability to see a product release as a set in Deployments and in the product's Deployments tab
- [x] Ability to promote the set dev proved, with each changed repository's changelog
- [x] Ability to import a catalog entry of several repositories as one product, retiring the products it replaces
- [x] Ability to build a commit of any of a product's repositories from the deploy dialog
- [ ] Ability to declare `dependsOn` on another repository's service in `deploy.yml` — the runner orders and checks it
  across a set; the shared generator still refuses it until a pipelines tag
- [ ] Ability to run Ocharo as one product on prod — the owner retires the two old products by importing `ocharo`,
  adds its environments, places it and deploys its first set after promoting this release

Proven by the runner, unit, integration, migration, E2E and console tiers and by `rehearse.py products`: ForeverPin cut
into two repositories' bundles, composed into a set and deployed over its single-repository release with no service
restarted and both baseline hosts answering. After the `product: ocharo` change each repository released (Platform
v0.1.9, Studio v0.1.7, Assets v0.1.1, each `ocharo-release.tar.gz`), so Ocharo's first set is
`platform-v0.1.9_studio-v0.1.7_assets-v0.1.1`. The runner downloaded, checked and composed Platform's and Studio's real
releases into one set locally (Desk the front door, Studio public); Assets is private, so its part waits for prod's
GitHub App, and the three descriptors compose offline with Motion private.
